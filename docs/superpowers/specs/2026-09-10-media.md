# sayAnything 图片与视频附件

用户指出无法上传图片/视频。根因是旧版本只有文字正文，没有选择器、上传接口或消息附件字段。本次保留校园人与人匿名聊天和灰度玻璃 UI，补齐私聊、话题房间、帖子和评论的媒体选择/上传/发送/查看。

## 契约

- POST `/api/v1/media`，Bearer 身份，multipart 单个 `file`。返回 Media `{id,kind:'image'|'video',mimeType,name,size,width?,height?}`。
- 支持 JPEG/PNG/WebP 图片（输入≤10MiB、解码≤25MP），MP4/WebM 视频（≤50MiB）。服务端依据文件内容验证类型；图片正确处理方向后重编码移除EXIF，视频不宣称清除元数据。不接受SVG/HTML/任意可执行文件。文件保存在独立MEDIA_DIR，不放在WEB_DIR。
- POST `/api/v1/media/{id}/ticket`，Bearer，校验用户是否能看到附件，返回 `{url,expiresAt}`，url为可直接播放/展示的相对URL，带独立短期令牌（不放用户session token）。
- GET/HEAD `/api/v1/media/{id}`，Bearer或短期ticket，读取时再次校验所属记录/校园/参与者/屏蔽/可见性；支持Range/206；private,no-store。未发送附件仅本人可访问。
- DELETE `/api/v1/media/{id}` 仅本人尚未绑定的附件，可用于取消选择后的清理。
- 原 posts、comments、room_messages、dm_messages 的POST新增可选 `mediaIds:string[]` 与 `clientId:string`（幂等），所有返回对象新增 `attachments:Media[]`，为空时可省略。旧文字接口兼容。
- 每条最多4个附件、客户端选择总量≤50MiB，允许纯附件无正文；有文字时仍执行原长度验证。仅能绑定本人上传的附件，绑定与内容入库需同一事务。clientId普通重试返回同一内容，不重复插入。
- 删除内容/账号应清理对应附件授权与文件；未使用上传定期清理；限制每用户待发送占用，避免无限堆积。旧数据库无损迁移，保留全部旧数据。
- 私聊列表纯图片/视频摘要使用「[图片]」/「[视频]」。举报和屏蔽同样适用于媒体内容。

## 客户端

Flutter官方 file_selector 选择本机文件；选择后在输入栏上方预览，可移除，点击发送才上传。共享MediaDraft管理队列、已上传ID和进度，失败保留文字和附件，重试复用已完成上传/幂等ID。上传中显示进度，空文字但有附件可以发送。图片点击打开可缩放查看页；视频点击打开可播放/暂停/进度控制页面，不在列表中自动播放。私聊/房间/发帖/评论共用附件组件。

界面控件保持灰度，用户上传的图片/视频保留本来颜色。视频使用现有 video_player；补上Windows平台播放器支持或诚实显示可用播放路径，不伪造播放成功。

## 验证

Go真实multipart+持久化+读取权限+Range测试，覆盖伪扩展名、越权绑定、跨校园、非参与者、屏蔽、删除、限额、纯附件与旧文字消息、幂等重试。Flutter单元/组件测试覆盖类型大小/草稿保留。浏览器使用真实图片和可播放MP4验证双用户收发与媒体查看，再构建Android与Windows发行包。
